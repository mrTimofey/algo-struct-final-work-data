# Инструменты итогового проекта

Два скрипта на Python без обязательных зависимостей: выгрузка района и генератор потока заказов. Форматы файлов описаны в приложении к заданию.

## extract_district.py

Готовит данные района: дорожную сеть и здания с адресами. Штатный вход — файл района из набора в [`data/`](../data/README.md):

```
python3 extract_district.py --osm-xml ../data/06-kazan-center.osm.gz --out work/district
```

Остальные режимы нужны для своего района:

```
# через OSMnx, по названию района
python3 extract_district.py --place "Академический район, Москва" --out data/akademichesky

# через OSMnx, по прямоугольнику west,south,east,north
python3 extract_district.py --bbox 37.55,55.68,37.60,55.71 --out data/bbox

# из файла OSM XML, без сторонних библиотек
python3 extract_district.py --osm-xml district.osm --out data/district
```

Режим `--place` и `--bbox` требует установленного `osmnx`. Режим `--osm-xml` работает на голой стандартной библиотеке и принимает `.osm`, `.osm.bz2`, `.osm.gz`.

Откуда взять OSM XML:

* BBBike: нарисовать полигон, выбрать формат OSM XML, получить файл на почту;
* Geofabrik: скачать округ и вырезать район утилитой osmium.

```
osmium extract -b 37.55,55.68,37.60,55.71 central-fed-district.osm.pbf -o district.osm
```

Дополнительно: `--clip-bbox` обрезает данные из XML прямоугольником, `--force` не даёт скрипту завершиться с ошибкой при непройденных порогах.

### Что скрипт делает и чего не делает

Граф намеренно не упрощается. Каждое ребро является прямым отрезком между двумя соседними точками дороги, поэтому его длина считается напрямую по координатам концов. Это делает требование «считайте длины сами» выполнимым без разбора геометрии.

Здания выгружаются контурами, а не точками. Сведение контура к точке входит в задание, поэтому скрипт этот шаг не делает. Здание, чей контур обрезан границей района, пропускается целиком. Адресная точка без контура попадает в справочник, только если это не заведение и не вход (у неё нет тегов `shop`, `amenity`, `office`, `entrance` и подобных) и если такого адреса нет у какого-либо контура.

Односторонние дороги учитываются: `oneway=yes` и `-1`, `junction=roundabout`, а также автомагистрали, односторонние по умолчанию. Двусторонняя дорога даёт два ребра, односторонняя одно.

Пороги пригодности района зашиты константами `MIN_NODES`, `MIN_BUILDINGS`, `MIN_STRONG_COMPONENT` в начале файла и должны совпадать с приложением. Доля сильно связной компоненты считается алгоритмом Косарайю, слабо связной — обходом по неориентированному представлению.

### Возможные затруднения

| Что видно | Причина и что делать |
| :---- | :---- |
| `Не найден osmnx` | Поставить `pip install osmnx` либо перейти в режим `--osm-xml` |
| Долгий ответ или ошибка сети в режиме `--place` | Ограничения Overpass API. Повторить позже либо взять данные через BBBike или Geofabrik |
| Мало зданий с адресом | В этом районе OpenStreetMap беден на теги `addr:*`. Нужен другой район |
| Низкая доля сильно связной компоненты | Прямоугольник разрезал сеть. Расширить границы либо сместить их |
| Вершин меньше порога | Район слишком мал. Учтите, что граф не упрощается, и в типичном городском районе получается от нескольких тысяч до нескольких десятков тысяч вершин |

## generate_orders.py

Создаёт поток заказов в свободной форме по зданиям района.

```
python3 generate_orders.py --district data/akademichesky --seed 4242 \
    --count 200 --missing-rate 0.07 --variant base --out orders/ --with-truth
```

Генератору нужна вся выгрузка района, а не только справочник: по `nodes.csv`, `edges.csv` и `building_points.csv` он выбирает здание для депо.

Результат полностью определяется значением `--seed`, сценарием `--variant` и списком улиц. При одинаковых параметрах файлы совпадают побайтово, что проверяется сравнением контрольных сумм.

| Ключ | Что задаёт |
| :---- | :---- |
| `--variant` | Сценарий доставки: `base`, `single`, `capacity` или `edge`. По умолчанию `base`. Состав сценариев описан в приложении |
| `--foreign-streets` | Файл со списком улиц для заказов с несуществующим адресом, по улице в строке, строки с `#` пропускаются. Без ключа берётся встроенный список `FOREIGN_STREETS` |

Кроме заказов генератор пишет `scenario.json`: идентификатор здания депо, число курьеров и вместимость в килограммах либо `null`. Решение читает этот файл, поэтому один и тот же код работает на любом сценарии.

### Как выбирается депо

Депо зависит только от района и сценария, от `seed` оно не зависит. Центр района — медиана координат зданий. В сценарии с депо в центре перебираются здания от ближайшего к центру, в сценарии `edge` — начиная с того, дальше которого лежит десятая часть зданий. Берётся первое здание, у которого все узлы сети в радиусе 200 метров лежат в наибольшей сильно связной компоненте. Радиус и долю задают константы `DEPOT_RADIUS_M` и `EDGE_QUANTILE`.

Вместимость в сценарии `capacity` на `CAPACITY_SLACK` (по умолчанию 20%) больше средней загрузки курьера, но не меньше средней загрузки плюс самый тяжёлый заказ, с округлением вверх. Нижняя граница гарантирует, что раскладка заказов по курьерам существует, в том числе для любого подмножества заказов.

Разметка `truth.csv` пишется только при флаге `--with-truth`. Без флага сохраняются только заказы, и правильные ответы остаются у того, кто запускал генератор.

### Как устроен шум

Шесть классов преобразований: сокращения и порядок частей адреса, склонение, опечатки по соседним клавишам, регистр и пунктуация, латинские двойники кириллических букв, лишний текст вокруг адреса. К одному заказу применяется от одного до трёх классов. Отдельно генерируются заказы с несуществующим адресом: несуществующий номер дома на существующей улице и улица, которой в районе нет. Номер чаще берётся из пропуска внутри диапазона улицы, реже — сразу за последним домом. Номер, с которого начинается корпус («12к2»), считается занятым.

Временное окно попадает только в текст заказа. В `orders.csv` отдельной колонки для него нет, потому что его извлечение регулярным выражением входит в задание.
